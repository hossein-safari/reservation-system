# امنیت و محدودیت‌ها

- رمز با Argon2 ذخیره می‌شود؛ هیچ رمز plaintext یا حساب مدیر پیش‌فرض وجود ندارد.
- JWT امضاشده HS256 دارای `sub`، `iat` و `exp` است. اعتبار نقش در هر درخواست از دیتابیس خوانده می‌شود. توکن بعد از خروج از UI تا انقضا معتبر می‌ماند؛ revoke/refresh token در نسخه پایه نیست.
- ثبت‌نام فیلد role قبول نمی‌کند. مسیرهای مدیریتی role را بررسی می‌کنند و query مالکیت مانع خواندن رزرو/پرداخت دیگری می‌شود.
- در مرورگر توکن فقط در حافظه است. TLS برای استقرار عمومی لازم است. از درج HTML خام استفاده نشده است.
- CORS فقط originهای صریح را می‌پذیرد. nginx هدرهای پایه امنیتی و CSP هم‌مبدأ دارد. تنظیمات محیط و اطلاعات اتصال در پاسخ خطا منتشر نمی‌شوند.
- درگاه توسعه انتقال وجه نمی‌کند و verify آن فقط در development/test مجاز است. اتصال درگاه واقعی نیازمند validation سمت سرور، امضای callback، تطبیق مبلغ/authority و reconciliation است. نباید موفقیت را از دادهٔ ارسالی مرورگر پذیرفت.
- logها نباید شامل رمز، Authorization یا جزئیات بانکی باشند. اطلاعات کارت اصلاً دریافت نمی‌شود.
- محدودسازی نرخ ورود، تأیید ایمیل، بازیابی رمز، audit log مدیریتی، اسکن وابستگی‌ها، مدیریت backup و سیاست نگهداری داده پیش از انتشار عمومی باید اضافه شوند.
- کنترل رزرو هم‌زمان در PostgreSQL به constraint متکی است. SQLite مسیر توسعه است و برای بار عملیاتی توصیه نمی‌شود.

پایهٔ فعلی برای توسعه و ارزیابی گردش کار است؛ چک‌لیست عملیاتی بالا بخشی از کار استقرار واقعی خواهد بود.
