# سیستم بصری دفتر قرار

رابط بر اساس صفحه‌آرایی دفترهای چاپی و جدول زمان ساخته شده است: زمینهٔ کاغذی، مرکب تیره، تأکید آجری، عنوان نسخ و خطوطی که اطلاعات را از هم جدا می‌کنند. ساختار اصلی شامل سرلوحهٔ افقی، فهرست بخش‌ها، حاشیهٔ معرفی و دفتر زمان‌هاست.

## پایه‌ها

| توکن | مقدار | کاربرد |
| --- | --- | --- |
| `--paper` | `#f3efe5` | زمینهٔ اصلی |
| `--paper-light` | `#fbf8f0` | سطح ورودی‌ها |
| `--paper-deep` | `#e8e0ce` | سرصفحهٔ روزها |
| `--ink` | `#292720` | متن، خطوط اصلی و دکمهٔ تأیید |
| `--accent` | `#a33f2b` | شمارهٔ بخش، تأکید و کنش hover |
| `--ink-soft` | `#71695d` | متن توضیحی |
| `--focus` | `#2456a4` | نشانهٔ فوکوس صفحه‌کلید |

Vazirmatn برای متن و اعداد، Noto Naskh Arabic با وزن ۶۰۰ برای عنوان‌ها استفاده می‌شود. هر دو فونت محلی و همراه build هستند. فاصله‌ها از مقیاس ۴، ۸، ۱۲، ۱۶، ۲۴، ۳۲، ۴۸ و ۶۴ پیکسل می‌آیند. گوشه‌ها مستقیم و سطوح بدون سایه‌اند.

مجوزهای فونت‌ها در `frontend/public/licenses/` قرار دارند و در خروجی سایت نیز با مسیر `/licenses/` منتشر می‌شوند.

## ساختار CSS

ورودی `frontend/src/styles.css` ترتیب cascade layerها را مشخص می‌کند:

1. `tokens.css`: رنگ، فونت، فاصله و عرض صفحه.
2. `base.css`: پیش‌فرض عناصر، آیکن، فوکوس و کاهش حرکت.
3. `layout.css`: سرلوحه، ناوبری، حاشیهٔ صفحه و صفحه‌بندی.
4. `booking.css`: جدول روزها، ردیف سانس، رزرو، رسید و وضعیت خالی/در حال دریافت.
5. `controls.css`: دکمه‌ها، فرم‌ها، پیام‌ها و dialog.

قواعد جدید را در لایهٔ مربوط قرار دهید. از رنگ پراکنده، کلاس سراسری مبهم و `!important` برای حل تداخل خودداری کنید؛ استثنا فقط تنظیم احترام به `prefers-reduced-motion` است.

## رفتار چیدمان

- سانس‌ها بر اساس **روز محلی تهران** گروه‌بندی می‌شوند. هر ردیف زمان شروع و پایان، نام فضا، مدت، قیمت و عمل رزرو دارد.
- تا عرض ۹۰۰ پیکسل، حاشیهٔ معرفی به بالای فهرست منتقل می‌شود؛ تا ۶۰۰ پیکسل، ردیف‌ها به ترکیب فشردهٔ زمان/فضا/قیمت/عمل تبدیل می‌شوند.
- وضعیت رزرو هم متن دارد و هم نشان رنگی. فرم‌های مدیریت، ورود و پرداخت از همان رنگ‌ها و هندسه استفاده می‌کنند.
- `Dialog` مشترک از عنصر native استفاده می‌کند تا فوکوس در پنجره باقی بماند و Escape آن را ببندد. هنگام انجام عملیات، بستن غیرفعال است.
- لینک عبور به محتوای اصلی، `aria-current` ناوبری، نام قابل‌تشخیص برای دکمهٔ هر سانس، فوکوس واضح و هدف‌های تعاملی حداقل ۴۴ پیکسل در نظر گرفته شده‌اند.

## بررسی بازطراحی

ESLint، Prettier، TypeScript، build و پنج تست فرانت اجرا شدند. تست جدید، گروه‌بندی روز تهران در مرز نیمه‌شب UTC و وضعیت رزرو هنگام انجام عملیات را پوشش می‌دهد. مرورگر واقعی، ورود و Escape، ثبت‌نام، فرم مدیریت، رزرو، dialog پرداخت و رسید را بررسی کرد. عرض‌های ۳۲۰، ۳۹۰، ۷۶۸، ۱۰۲۴، ۱۴۴۰ و ۱۹۲۰ پیکسل بدون اسکرول افقی بررسی شدند.
